Integration and auth boundary — one server, two simulated seams

One Cloudflare Pages Function over D1 is the only server. The browser's Documenso and Xero integrations build real payload shapes locally; the guard is the only thing in front of auth.handler, and nothing leaves the process today.

01 · One server

The only server component

A single Cloudflare Pages Function, functions/api/[[route]].ts, runs Hono, better-auth and Drizzle over D1 crmv2-auth. Everything else is browser code.

02 · The guard

Only the guard sits in front

Every /sign-up path returns 403, and role, staffId and kind are stripped from other JSON auth POSTs. The 10 seeded accounts are created server-side and never cross that route.

03 · Two seams

Real shapes, no wire

documenso.ts and xero.ts build real envelope and ACCREC payloads without a fetch. Credentials in integrationConfig stay unused, and the three external systems remain unwired.
