# CRMv2 Full UI Redesign + Feature Expansion — Design Document

**Date:** 2026-11-09 · **Status:** awaiting user approval
**Destination (commit during execution):** `docs/superpowers/specs/2026-11-09-crm-redesign-design.md`
**Project:** `/home/hein/Projects/CRMv2` — FD on Call practice CRM (React 19 + Vite + Tailwind v4 + shadcn-style, no router lib, `PracticeStoreContext` + localStorage, domain engine in `packages/domain`).

---

## 1. Intent & Why

FD on Call wants the whole CRM restyled to the layouts in 8 design-reference bundles (project-workspace dashboard, analytics overview, CRM contact profile, invoice builder, kanban board, role-permissions matrix, time-tracking report, sales pipeline) while keeping the FD on Call brand (crimson `#c4161c`, Instrument Serif + Geist, paper/dark canvases) and keeping every statutory/domain rule intact. On top of the restyle, four new capability areas: a quote→signature→invoice flow, a sales pipeline + deadlines boards with detail panels, granular role permissions (incl. a Support Tech role), and time tracking that feeds invoicing. The old client prototype (`/home/hein/Projects/CRM/Client_CRM`) is a requirements source only — its UI is never copied. The reference images' fictional content (NimbleBuild, Riverside Hub, Jordan Lee, etc.) never enters the app; only composition, hierarchy, and component anatomy do.

## 2. Goals (each maps to user-confirmed outcomes)

1. **Home** = project-workspace-dashboard layout: greeting + search + `+ New` + avatar; engagement banner with progress; KPI strip; My Tasks card (tabs); Team Activity feed; empty-state cards; right rail: Upcoming Deadlines, Recent Work, Invite card. All data practice-real.
2. **New Analytics page** = analytics-overview layout: eyebrow/H1, date-range + compare pills, 7D/30D/90D/1Y segmented control, hero metric with line chart + Δ vs previous, 3 KPI cards, category donut, horizontal bar list, recent activity. Metrics practice-defined (§6.6).
3. **Client record + person profile** = crm-contact-profile layout: identity header, contact meta, tag pills, tabs, 3-column grid (Contact Details, Missing Information, Organization, Relationship History, Next Action, Internal Notes, Tags). Statutory tabs preserved (§6.3).
4. **Quote builder** = invoice-builder two-pane pattern (form + live document preview) but accounting-domain content: client search-select, engagement scope from service catalogue (grouped toggles), fee schedule generated by the 12-month matrix engine, VAT toggle, payment terms. Quote lifecycle: Draft → Sent → Accepted → Signed → Active Client (+ Closed Lost), then Invoice auto-created.
5. **Two kanban boards** in kanban-project-board anatomy (columns w/ counts, cards w/ labels/owner/due/blocked, right detail panel, keyboard moves, subtask-free): Sales Pipeline (quotes to prospects) and Deadlines (statutory work, 6 lanes). Both boards get kanban **and** table/list views.
6. **Permissions matrix** in Settings: 6 roles (incl. Support Tech), grouped permission rows, Allowed/Not-allowed/Limited/Inherited/Custom cell states, legend, role-details panel, high-impact confirmation dialog. Founders (Partners) and Support Tech manage permissions.
7. **Time tracking**: live timer + manual entries, client/service/task linkage, billable flag, 15-min rounding, timesheet + report views (time-tracking-report layout), billable time feeds invoicing (Epic 6 retainer depletion + overage).
8. **Theme**: dark stays the default; light/dark toggle kept; every new/changed screen works in both themes using the existing token system (`apps/web/src/index.css`). Brand colors/fonts unchanged.
9. **SAICA Governance Log** stays: read-only, auto-appended from partner sign-offs/submissions, in Settings, with PDF/CSV export.

## 3. Non-goals & anti-goals

**Non-goals:** no database/backend migration now (data stays in the local store, §4.4); no live Documenso/Xero API calls now (integration layer + simulated adapters built ready, real wiring is a defined follow-up once credentials exist); no client-facing portal; no live in-app signature capture (signature recorded as an envelope record on the call); no change to statutory date/pricing math in `packages/domain`.

**Anti-goals (what would make this a failure even if it "works"):** losing any existing capability (inbox, command palette, division switcher, AI assistant drawer, PDF/XLSX exports, partner review gates); fictional reference content leaking into the product; empty data rendering as zero; breaking the existing test suites; a screen that only works in one theme.

## 4. Constraints

1. Stack frozen: React 19, Vite, Tailwind v4, shadcn-style primitives, `@tanstack/react-table`, no react-router (in-memory `ViewKey` in `apps/web/src/App.tsx`).
2. All practice state in `PracticeStoreContext` (`apps/web/src/context/PracticeStoreContext.tsx`), persisted to `localStorage` key `crmv2_practice_state`. New entities (quotes, invoices, time entries, permissions) extend this store; reducer actions + persistence follow the existing pattern.
3. Domain engine (`packages/domain/src/domain/*`, `src/export/*`) is authoritative for statutory rules, deadlines, pricing, and estimate math. UI never re-implements them. Restore the prototype's estimator controls that CRMv2 dropped (§6.4).
4. Both themes mandatory; use existing tokens (`bg-card`, `border-border`, `text-foreground/muted-foreground`, `text-primary`, crimson `#c4161c` inline accents as today). No new color family. Reference geometry (radii, spacing, hierarchy) is adopted; reference accent colors (blue/green/mint) are replaced by brand crimson + neutral tokens.
5. Accessibility: keyboard paths for boards (arrow keys + number keys), visible focus, reduced-motion respect, semantic buttons vs links, empty/error states on every data-driven region.
6. Existing tests (`npm test` workspace-wide) must pass after every phase; behavior-defining tests for new logic added.
7. **UI craft**: the user wants "normal", non-slop product UI at the level of the references. Implementation MUST follow the `impeccable` skill (craft floor) and `frontend-design` skill guidance for every screen; polish is part of "done", not a follow-up. Screens are judged against the reference compositions (§6.2–6.9), not a generic template.

## 5. Approaches considered & picks

1. **Restyle strategy** — (a) build a new component layer mimicking the reference anatomy with FD on Call tokens, screen by screen; (b) theme-swap the whole app's colors only; (c) port reference screens wholesale (fictional content). **Pick (a):** (b) doesn't deliver the layouts, (c) violates anti-goal 2.
2. **Quote flow** — (a) one builder for prospects + existing clients, matrix engine feeds the fee schedule; (b) two separate flows. **Pick (a):** existing clients pre-load services + last estimate; single lifecycle.
3. **Boards** — (a) one shared kanban component (column/card/detail-panel anatomy) reused by Sales Pipeline + Deadlines; (b) two bespoke boards. **Pick (a):** identical interaction model (drag + keyboard + detail panel), different card/column data.
4. **Permissions** — (a) new granular `PermissionState` model + matrix UI with 6 roles; (b) keep coarse role strings + one gate. **Pick (a):** user requires matrix with inherited/custom states and Support Tech editing.
5. **Data layer** — (a) extend the localStorage store; (b) move to D1/backend now. **Pick (a)** (user-confirmed): zero backend risk, consistent architecture; DB migration remains future work.
6. **Integrations** — (a) simulate now + wire later (user-confirmed): in-app flow complete with simulated Documenso envelope records + Xero draft payload previews, integration service interface + credentials settings built ready; (b) real API wiring now (rejected: no credentials/instance). Research findings recorded: Documenso self-hosts via Docker (+ Postgres, SMTP, HTTPS domain; REST API v2, `Authorization: api_…`, `X-Documenso-Secret` webhook header — note: repo doc `docs/03`'s HMAC `X-Documenso-Signature` is outdated); Xero needs a free connected app (scopes `accounting.transactions` + `accounting.settings`), OAuth2 + tenant id from `/connections`, invoices as `ACCREC`/`DRAFT`/`LineAmountTypes: Exclusive`/`TaxType: OUTPUT2` on revenue accounts; free demo company for testing.
7. **Build order** — one plan, four ordered phases (user-confirmed): (1) theme/layout foundation + all screen restyles; (2) quote→invoice flow; (3) time tracking; (4) permissions matrix + roles. Tests green after each phase.

## 6. The how — decided details

### 6.1 Global shell & navigation

- **Sidebar** (both themes): brand block (division-aware logo, `FD on Call`/`Accountant on Call` per current division switcher), nav items with icon + label, active item = crimson-tinted rounded background (reference anatomy), footer user popover retained. Items grouped: `Practice` = **Home**, **Analytics** (new), **Inbox** (unread badge from partner-review count); `Work` = **Clients**, **Team** (was People — see §6.3), **Deadlines** (overdue badge), **Sales Pipeline** (new, replaces the unreachable pipeline view), **Time** (new); `Admin` = **Settings**, **Governance Log** (new, read-only audit view — see §6.12). Group labels mirror the reference style.
- **Topbar**: breadcrumbs retained; search trigger retained (`Cmd+K` command dialog, now also searching quotes + time entries by client); theme toggle retained; `+ New` button opens a menu: New Quote (→ quote builder), New Client (→ clients view w/ create), Log Time (→ time view w/ entry modal). Avatar = current user initials popover (retained).
- **Manual ad-hoc tasks**: the kanban reference's `+ Add a task` column action is implemented on the Deadlines board only, creating an `AD_HOC` task (client, description, assignee, due date; no statutory due logic — the `AD_HOC` service code already exists in the domain spec). Ad-hoc tasks are editable/deletable and flow through the same lanes; they never receive partner-review gates.
- **Routing**: extend `ViewKey` in `apps/web/src/types/navigation.ts` with `analytics | sales-pipeline | time`; `App.tsx` switch maps them; `NAV_ITEMS` in `apps/web/src/components/layout/navigation-helpers.ts` updated; the legacy `estimator | quote | pipeline` keys and the standalone `EstimatorView`/`PipelineView` mappings are removed (clean cutover): the 12-month calculator's inputs move into the quote builder's fee-schedule step, `SentQuotesPipeline` becomes the Sales Pipeline board's quotes list, `OnboardingPipeline`'s convert logic moves behind the quote `Active Client` transition. No dead views, no shims.
- **Layout component**: page header pattern (eyebrow, H1 serif, subtitle, right controls) introduced as a shared `PageHeader` component and used by all views; content wrapped in consistent max-width + padding.

### 6.2 Home (project-workspace anatomy, practice data)

- Greeting: `Good {morning|afternoon|evening}, {currentUser.name}` + subtitle. Search + `+ New` + avatar right-aligned.
- **Engagement banner**: the client with the most open statutory tasks this period. Title + entity badge; subtitle = practice line (e.g. "Current statutory engagement"); progress bar = % of that client's obligations submitted/approved (label: `Compliance`, `N% complete`); right action `Open Client →` routes to `/clients/:code`. If no clients have open tasks → banner shows practice-wide compliance % instead. Never a fictional project.
- **KPI strip** (computed from store, not seeded): `Total tasks` (open tasks), `Due this week`, `In review` (Partner Review Gate count), `Team members` (staff count). Each links to the filtered Deadlines view.
- **My Tasks card**: tabs `My tasks (n)` / `Completed (m)`; rows = tasks assigned to current user: checkbox (toggles complete → Submitted for gate-free tasks, opens action modal for gated ones), title, subtitle `{Client} · {Service}`, priority pill High/Medium/Low (from urgency: overdue→High, ≤7d→High/Medium, ≤30d→Medium, else Low), due date right-aligned (Today/date, red when overdue). `View all →` = Deadlines filtered to current user.
- **Team Activity card**: feed of recent store events (task status changes, submissions, quote stage moves, time logged, files added) + seeded historical items; avatar initials w/ tinted backgrounds, action text, subline (client/asset), relative timestamp (`2h ago`).
- **Empty-state pair**: `No overdue tasks` (when overdue count = 0) and `No tasks awaiting client` (Awaiting Client count = 0), dashed-border cards.
- **Right rail**: `Upcoming Deadlines` (next 5 due tasks: month/day date chip, title, client, priority pill; `View calendar →` = Deadlines), `Recent Work` (last time entries + recent vault files, thumbnail/icon, `Edited Xh ago · Name`; `View all →` = Time view), `SA Public Holidays` (next 2–3 gazetted holidays — carries today's dashboard holidays content forward, no feature loss), `Invite your team` tinted card → Team pane in Settings.
- **Retained chrome**: `AiPracticeAssistantDrawer` and the `Cmd+K` command dialog stay (restyled, same triggers); division switcher stays; nothing existing is dropped.

### 6.3 Client record & person profile (crm-contact-profile anatomy)

- **Header**: avatar (initials/logo tile), legal name + monospace code badge, subtitle `{Entity type} · {Group}` + description (client notes first line, else group name), tag pills from services/entity, right meta column: email, phone, location, timezone (new optional fields — most seeds lack them → `—`), `+ Add Action` (opens: Log Time / New Quote / Add Note).
- **Tabs**: `Overview` (identity + statutory profile — current `StatutoryProfileTab` content restyled to the 3-col grid), `Organization` (directors/group members — people table filtered to this client), `History` (relationship timeline: interaction entries + filing milestones, newest first, dot+connector anatomy), `Tasks` (client's deadlines — current DeadlinesTab content, restyled), `Estimate` (12-mo matrix, wire the existing `EstimateTab`), `Vault` (wire the existing `VaultTab` — SharePoint folders + Documenso/SLA), `Notes` (internal notes only).
- **3-column grid on Overview**: left = `Contact Details` (label:value rows; empty values render `—` + `Add` link) + `Missing Information` (lists unfilled statutory/contact fields with `Add` links — replaces today's ad-hoc warnings); middle = `Organization` (group + members summary, industry→`Entity type`, size→turnover band, website→`—`) + `Relationship History` (same timeline as History tab, top 4); right = `Next Action` (the client's earliest open task: date, title, `Mark Complete` opens the statutory action modal) + `Internal Notes` (private, visually distinct callout, labeled `Internal`) + `Tags` (pills + manage).
- **People directory → Team** (staff only): the current mixed directors+staff directory is split. `Team` = internal staff records: name, role, kind (employee/subcontractor), email/phone, start date, and contract details (contract type, hourly rate for subcontractors) — a staff HR register, not client data. Client **directors & contacts move onto each client's `Organization` tab** (people list + director/contact records owned by that client, editable there; seeded directors migrate over). Person profiles (identity header + contact details + history + notes) apply to staff and client contacts alike.
- Keep: summary bar quick actions (`Export PDF Quote`, `View Client Deadlines`) and the deep-link to the Deadlines board.

### 6.4 Quote builder + lifecycle (invoice-builder pattern, accounting-domain content)

- **Entry points**: `+ New` → New Quote; Sales Pipeline `+ New Quote`; client record → `New Quote`/Estimate tab `Re-quote`.
- **Client step**: search-as-you-type select (existing clients pop up; pick fills client details, statutory fields, services on record, last estimate). Or "New prospect": name, entity type (incl. Close corporation — restore the missing option), contact person, turnover, payroll, VAT, year-end, incorporation date, responsible staff. Prospect stays unregistered until Converted.
- **Scope step**: five service groups as toggles (from the client prototype): Regular work, Compliance, Annual work, Recharges, Once-off setup. Toggle = add-on selection; applicability rules from `packages/domain` (`applicable`, `suggestedSelection`).
- **Fee schedule step**: the 12-month matrix engine (`computeEstimate`) generates per-month fee lines + Year total. Restore the dropped controls: schedule frequency per regular-work line (monthly / with each VAT return / chosen months), editable directors count, provisional-taxpayer switch, start-month select, IRP6 outcome selector (nil/payable affects fee + review), hourly-rate + March-increase fields, `Reset to pricing bands`. Overrides mark lines `touched` (prototype semantics). CIPC fees stay VAT-exempt; recharges at cost. VAT excl/incl toggle; totals reconciled line-by-line (cent-exact, engine rules).
- **Document preview (right pane, live)**: FD on Call branded A4-style preview: logo, `Quote` + `Q-<seq>` + issue/expiry, Prepared for block, fee schedule table (grouped lines, subtotals), Subtotal / VAT 15% / Total band, payment terms, notes ("estimate, not a fixed fee…"), signature blocks (Client + Partner). Buttons: `Save Draft`, `Send Quote` (→ Sent), `Mark Accepted` (staff records client's yes on the call), `Send for Signature` (opens the Documenso dispatch dialog → records envelope, dual signer: client signatory + partner; simulated), `Create Invoice`, `Download PDF` (existing exporter), `Download Excel`.
- **Stages** (sales pipeline board tracks these): `Draft Quote` → `Quote Sent` → `Accepted` → `Signed` → `Active Client`, plus `Closed Lost`. Transition rules: Send requires client selected + ≥1 fee line; Accept requires Sent; Sign requires Accepted; Active Client requires Signed (conversion = today's `CONVERT_LEAD` behavior: create client, assign services, materialize tasks, note "Added from a fee quote"). Closed Lost allowed from Draft/Sent/Accepted only.
- **Existing leads migration (clean cutover, no capability loss)**: the `leads` entity, `OnboardingPipeline`, `SentQuotesPipeline`/`QUOTE_STAGES`, and `ADD_LEAD`/`UPDATE_LEAD_STAGE`/`CONVERT_LEAD` actions are removed; the 4 seeded leads become quotes with stage mapping: `Lead`/`Discovery` → `Draft Quote`, `Estimate Sent` → `Quote Sent`, `KYC & Transfer` → `Accepted` (KYC runs between accept and sign), `Active Client` → `Active Client` (their `estimatedMonthlyFee` becomes the initial fee-schedule value; owner/contact carried over). Prospect tracking stays possible: a prospect without a fee schedule is simply a `Draft Quote` card. The AI assistant's lead counts switch to open-quote counts. A one-time `MIGRATE_LEADS` reducer path converts persisted old-state `leads` on load.
- **Invoice auto-creation**: `Create Invoice` (enabled at Accepted) creates the invoice for the **next unbilled month** of the quote's fee schedule (user picks the month in the confirm step; default = next month after the last invoiced one). Invoice lines = that month's fee lines + any unbilled time lines (§6.5); user can edit before save. `INV-<seq>` numbering, issue/due dates (due = payment terms from quote), tax rule 15%, status `Draft`. Recurring billing = repeat `Create Invoice` per month (no automatic scheduler — practice is manual, matching Epic 6's partner-triggered sync). `Send` → `Sent`; `Mark Paid`; `Overdue` is derived at render (due < today, not Paid, not Draft) — never stored. Xero pane on the invoice: "Push to Xero (draft)" previews the exact `ACCREC`/`DRAFT`/`OUTPUT2` payload (existing `buildXeroInvoiceDraft` logic, restyled) and records a simulated sync result. Invoice list lives under a `Quotes & Invoices` section of the Sales Pipeline view (tabs: Pipeline board / Quotes list / Invoices list) — invoices never orphaned in a modal-only flow.
- **Quotes/invoices data**: new store entities (§6.8); existing `savedEstimates` retained for the client Estimate tab.
- **Quote persistence**: a Quote stores its full `estimateInput: EstimateInput` as the authoritative record; `feeSchedule` is a derived cache recomputed via `computeEstimate` on every edit (scope toggle, directors count, provisional switch, start month, rates). This keeps saved drafts fully editable and re-quotable.
- **Scope → statutory tasks on conversion**: `packages/domain/src/domain/types.ts` `Client` gains optional `services?: ServiceCode[]` (matches the DB spec's planned `service_overrides`); `defaultServices(c)` in `rules.ts` becomes `c.services ?? derive-from-attributes` (existing seed clients have no `services`, so their derivation is byte-identical today — zero behavior change). Quote conversion sets `client.services = servicesFromEstimate(quote.estimateInput)` and `savedEstimates[client.code] = input`; the StatutoryProfileTab service checkboxes write the same explicit list instead of deriving from attributes. A re-quote for an existing client ("Save and update services") replaces the list, exactly like the client's prototype.

### 6.5 Time tracking (time-tracking-report anatomy + timer)

- **Entry model**: client, service/task (optional), staff user, start/end or duration, description, billable (default true), rounded to **nearest 0.25h (half-up) per entry**, min 0.25h; rounding rule displayed on the report. Entries spanning midnight allowed (duration from start/end).
- **Retainer allowance & rates (Epic 6)**: a Quote stores `monthlyRetainerHours` (sum of the fee schedule's regular-work hours — bookkeeping + payroll + management — for month 1; editable) and `adHocHourlyRate` (default R625 = `rates.standardHourlyRate`; editable — this is the "R625/R850" knob). On the client, the accepted quote's values become the billing baseline. Invoice time lines: billable hours within the monthly allowance are covered by the retainer fee line (no extra charge); hours beyond the allowance become overage lines at `adHocHourlyRate`, 15% VAT, per Epic 6's depletion math.
- **Timer**: global running-timer indicator in the topbar (client + elapsed, pause/stop); timer start also from task detail panels and client `+ Add Action`. Stop → entry created (editable before save).
- **Time view** (sidebar `Time`): tab 1 `Log` = timesheet (date filter, add/edit/delete entries, per-row billable toggle, manual duration input); tab 2 `Report` = reference layout: date-range + Project/Person/Task filters + Apply/Clear, 4 KPI cards (Total (rounded), Billable, Non-billable, Billable %), grouped expandable table (Project → person+task rows, Billable | Non-billable | Total columns, all reconcile to entry sums), Time by Project bars, Billable vs Non-billable donut, Rounding Rules card (`Round entries to 0.25h`, `Minimum entry 0.25h`, `Apply rounding Per entry`).
- **Invoice feed**: on an invoice for a client, an `Add unbilled time` action lists that client's unbilled billable entries in the period → appends lines: retainer-depletion split (hours within the retainer allowance at the contracted rate vs overage at the hourly rate, Epic 6 math) with 15% VAT. Report separates billable/non-billable everywhere.

### 6.6 Analytics page (analytics-overview anatomy, practice metrics)

- Controls: date-range pill + compare-period pill + 7D/30D/90D/1Y segmented control; units/denominators shown per metric.
- Hero metric: **Billed revenue** (ZAR, sum of Paid+Sent invoice totals in period) + Δ% vs previous period + line chart by month (revenue), endpoint callout.
- KPI row: `Active clients` (Δ vs previous), `Filings submitted` (Δ), `Billable hours` (Δ).
- Category donut: revenue by service group (Regular/Compliance/Annual/Recharges/Once-off) with legend % + ZAR.
- Bar list: hours by client (top 5).
- Recent activity list (reuse the Team Activity data).
- Missing-data rule: no invoices/time in period → explicit empty states ("No revenue recorded this period"), never zero-fakes. % changes = (current − previous)/previous with stated basis; zero-denominator renders `—`.

### 6.7 Boards (shared kanban anatomy, two instances)

- **Shared component**: `KanbanBoard` (columns w/ dot + name + count + `+ Add`, draggable cards, hover `…` menu, keyboard: ←/→ move columns, ↑/↓ move within column, 1–N jump to column; card detail panel: status dropdown, meta rows (owner/due/labels), description, activity, comment box; blocked cards red-tinted with `ⓘ Blocked: {reason}`; label pills from a fixed palette; keyboard-shortcut hint box). Drag never the only path (menu + keys).
- **Sales Pipeline board**: stages = quote stages (§6.4). Cards = quote/prospect: company, monthly fee (ZAR), owner avatar, next step (e.g. `Intro call`, `Send proposal`, `Signature`), aging chip (days in stage; amber ≥15). KPI pair above: `Booked` (Active Client total) vs `Open pipeline value` (non-lost sum) — explicitly separated. Pipeline snapshot donut by stage (value share). `+ New Quote` opens builder. Table view: quote register (prospect, stage, value, owner, next step, age) + tab for invoices.
- **Deadlines board**: 6 lanes `Not Started → In Progress → Awaiting Client → Partner Review Gate → Approved (Ready to Lodge) → Submitted`. Cards = statutory tasks: client code, service, due date w/ rollback tag, assignee avatar, urgency pill, partner-review badge, blocked = missing master data (e.g. `Missing incorporation date`). Detail panel = existing `StatutoryActionModal` content restructured as a panel (status select, IRP6 outcome, partner sign-off gate, SARS reference, submission date). Gate rules unchanged (`needsReview`, `canSignOffPartnerGate`). Keyboard 1–6 = lanes. Table view = existing `DeadlinesTable` restyled. KPI tiles + filters retained (workflow/urgency grouping both kept).
- Both boards respect the existing `groupBy`/filter controls and the client-filter deep-link.

### 6.8 Settings, permissions matrix & roles

- **Roles** (6): `Partner`, `Compliance Officer`, `Accountant`, `Team member`, `Subcontractor`, `Support Tech` (new — external IT/admin support: full settings + permissions management + governance log view + people/account help; **no client, deadline, quote, invoice, or time data** — the §6.9 matrix is the source of truth).
- **Permission model**: `PermissionState` in the store: roles fixed; groups = `Clients`, `Deadlines & Tasks`, `Quotes & Invoices`, `Time`, `People`, `Settings`; rows per group = view/create/edit/delete (+ special rows: `Submit returns`, `Partner sign-off`, `Manage permissions`, `View billing`); cell states = Allowed / Not allowed / Limited / Inherited / Custom. Defaults (§6.9) shipped as the initial matrix; Support Tech + Partner may override any cell (Custom) — overrides require the high-impact confirmation dialog that names the actual change ("You're enabling X for role Y…"), and limited/ambiguous states are disallowed at save.
- **Settings nav** — rebuilt as a standard, familiar settings UX (left grouped nav + right content pane, reference aesthetics): `Profile` (name, email, avatar), `Appearance` (theme light/dark/system — the existing toggle's home), `Team & Staff` (employee register incl. contract details + invites), **`Roles & Permissions`** (matrix UI per reference: legend, grouped rows, role columns, role-details panel with permission summary counts + custom toggles + info callout, `Create Role` disabled → roles fixed by store), `Practice Rules` (Service & Pricing Matrix, SA Public Holidays — wire the existing unwired pane), `Integrations` (Documenso, Xero, AI — wire the existing unwired AI pane; credential placeholders per §6.11), `Notifications` (simple email preferences, seeded). The governance log is **not** in Settings — see §6.12.
- **Governance Log (own sidebar view)**: read-only, auto-appended practice audit trail — entries appear automatically from partner sign-offs, submissions (SARS reference, return, client, date, approver), quote accept/sign, invoice create/send, and permission changes (who changed what, when). Export CSV/PDF. This is the SAICA/IRBA engagement-quality-review evidence (ISQM 1-style): the practice needs the trail as a first-class record, not a settings pane. Additionally, each client's `History` tab shows the same trail filtered to that client (all events touching that client), satisfying the "log on the Clients screen" instinct — the per-client trail lives there; the global trail lives in the Governance Log view.
- **Enforcement**: replace the single `isPartnerOrAdmin` gate with permission checks (`can(userRole, 'group.action')` helper in a new `permissions.ts`): Settings visibility, quote send/accept, invoice create/send, time edit, people invite, task submit/sign-off. Existing partner-gate logic unchanged in behavior.

(A = Allowed, Not = Not allowed, Limited = limited scope). **Support Tech is a system-admin role, not a practice user**: it sees no client records, no deadlines, no quotes/invoices/time — only People (invite/account help), Settings, permissions, and the governance log; this satisfies "founders or the support tech can change permission" without exposing billing. The **partner sign-off row is locked** (practice rule, not matrix-overridable): cells render with a lock marker and are disabled; enforcement keeps `canSignOffPartnerGate` (`role === 'Partner'`) exactly as today.
